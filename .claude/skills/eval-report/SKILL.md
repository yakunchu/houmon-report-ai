# 評価の実行と読み解き

## 今回の評価結果（`npm run eval` の出力）

!`npm run eval || true`

## やること
上の出力（欄ごとの「見本 / 実際 / 一致」の差分表）を読み、次の順で整理してください。

1. **サマリ**: 選択式の一致数（合格ラインは 100%）、「要確認」にすべき欄が推測で埋まっていないか、S の引用が台本に実在するか、マスク記号以外の氏名が出力に無いか
2. **落ちた欄ごとの表**: 欄名 / 見本 / 実際 / 台本のどの発話が根拠か（`fixtures/yamamoto-hanako/transcript.md` から引用）/ `prompts/report-rules.md` のどの文を直すか（現行の文を引用し、修正案を添える）
3. **備考・SOAP の差**: 人が判定する欄は、意味の欠落（数値・頻度・依頼文）と、会話に無い事実の追加を重点的に見る
4. 修正案は一般化して書く。**見本の文をそのままルールに入れない**（評価が意味を失う）。方針は `houmon-report-rules` スキルに従う

## 適用について
- 提案までが既定。**`prompts/report-rules.md` を実際に書き換えるのは、ユーザーが指示したときだけ**
- 適用する場合の手順: `.md` だけを直す → `npm run gen:prompt` → もう一度 `npm run eval`（再び費用が掛かるので、実行前に一言断る）→ `eval-results/history.md` の記録を確認
- 実行に失敗した（キー未設定・残高不足・スキーマ 400）場合は、出力をそのまま示して原因を説明し、残高不足なら社長に知らせる
- 失敗しても埋め込みは `|| true` で終了コードを握りつぶすので、スキル本文は必ず届く。差分表が無くエラー文だけのときは失敗とみなす（終了コードでは判別できない）。事前承認は frontmatter の `allowed-tools` で行う（無いと埋め込み自体が権限確認で中断する）
