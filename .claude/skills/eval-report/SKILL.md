## 別の台本・宛先で評価したいとき（引数付きは手で実行する）
埋め込みコマンドの中で引数が展開されるかは、公式ドキュメントで確かめられませんでした（確かめたのは「引数の展開」と「コマンド埋め込み」それぞれの仕様だけ。末尾の出典を参照）。そのため埋め込みは引数なしに固定し、引数付きの評価は次の手順にします。

1. ターミナルで手動実行する（リポジトリ直下。`npm run eval` は API を呼ぶので費用が掛かる）。
   - 既定（山本花子さん・ケアマネ宛）: `npm run eval`
   - 医師宛（佐々木清さん）: `npm run eval -- --fixture=fixtures/sasaki-kiyoshi --recipient=医療機関`
   - 聞き返し台本: `npm run eval -- --fixture=fixtures/yamamoto-hanako-kikikaeshi`
   - 新しい患者の想定（基本情報 5 項目を空にして送る）: `npm run eval -- --new-patient`
   - 送る内容だけ確認（API を呼ばない・無料・何も保存しない）: `npm run eval -- --dry-run`
   - 引数は組み合わせられる。history.md のメモ欄に一言残すなら `--note=メモ`
2. 終わったら、`eval-results/history.md` の最終行と、同フォルダの最新の JSON（`<日時>-<model>-<effort>.json`）を読み、下の「やること」の整理を行う（`report-qa` サブエージェントに任せてもよい）。

**`/eval-report` に引数を付けても、評価の対象は変わりません。** 埋め込みは既定の評価を実行し、付けた引数はこの文書の最後に `ARGUMENTS: …` として足されるだけです。末尾にその行が付いていたら、既定の評価が 1 回走った（費用が掛かった）ことをユーザーに伝え、引数付きの評価は上の手順で手実行するよう案内してください。ユーザーの指示なしに追加の `npm run eval` を実行しない。

## やること
上の出力（欄ごとの「見本 / 実際 / 一致」の差分表）を読み、次の順で整理してください。

1. **サマリ**: 選択式の一致数（合格ラインは 100%）、「要確認」にすべき欄が推測で埋まっていないか、S の引用が台本に実在するか、マスク記号以外の氏名が出力に無いか
2. **落ちた欄ごとの表**: 欄名 / 見本 / 実際 / 台本のどの発話が根拠か（評価した台本 `fixtures/<フォルダ>/transcript.md` から引用。既定は `fixtures/yamamoto-hanako/transcript.md`）/ `prompts/report-rules.md` のどの文を直すか（現行の文を引用し、修正案を添える）
3. **備考・SOAP の差**: 人が判定する欄は、意味の欠落（数値・頻度・依頼文）と、会話に無い事実の追加を重点的に見る
4. 修正案は一般化して書く。**見本の文をそのままルールに入れない**（評価が意味を失う）。方針は `houmon-report-rules` スキルに従う

## 適用について
- 提案までが既定。**`prompts/report-rules.md` を実際に書き換えるのは、ユーザーが指示したときだけ**
- 適用する場合の手順: `.md` だけを直す → `npm run gen:prompt` → もう一度 `npm run eval`（再び費用が掛かるので、実行前に一言断る）→ `eval-results/history.md` の記録を確認
- 実行に失敗した（キー未設定・残高不足・スキーマ 400）場合は、出力をそのまま示して原因を説明し、残高不足なら社長に知らせる
- 失敗しても埋め込みは `|| true` で終了コードを握りつぶすので、スキル本文は必ず届く。差分表が無くエラー文だけのときは失敗とみなす（終了コードでは判別できない）。事前承認は frontmatter の `allowed-tools` で行う（無いと埋め込み自体が権限確認で中断する）。`Bash(npm run eval *)` は末尾に任意の引数が付く `npm run eval -- --dry-run` なども事前承認する（出典の公式ドキュメントで、末尾の `*` が引数を表すことを確認）
