### 時間配分（1 分 300 字で換算）

| 区間 | 枠 | 字数（句読点を含み「」と空白を除く） | 読み上げ目安 |
|---|---|---|---|
| 0:00–0:20 | 20 秒 | 132 | 約 26 秒 |
| 0:20–0:45 | 25 秒 | 111 | 約 22 秒 |
| 0:45–1:05 | 20 秒 | 110 | 約 22 秒 |
| 1:05–1:15 | 10 秒 | 48 | 約 10 秒 |
| 1:15–1:38 | 23 秒 | 89 | 約 18 秒 |

字数の合計は 890 字（2026-11-07 に数え直し）で、1 分 300 字のペースだと約 2 分 58 秒。3 分の枠に入るが**余裕は 2 秒しかない**。行ごとの長さには偏りがある（0:00–0:20 と 2:30–2:50 は枠より 6〜10 秒長く、1:15–2:30 は余る）。ナレーションは後録りなので、詰まった行は隣の余る行に食い込ませて吸収し、行の境界は編集で動かす。撮影前に声に出して 1 回通し、全体が長ければ、①の「介護職の方も同じ画面を使えます。」を残したまま、先に 1:38–2:02 の「印刷・FAX、メール、チャットも選べます。」と 2:30–2:50 の「個人情報の混入はサブエージェントが監査し、」の説明を短く削る。早口にならないよう、待ち時間（下書き生成の 10〜17 秒）は編集で詰める。

### 収録方法の選び方

- **A. iPhone 実機の画面収録（アプリ画面 0:20–2:30 の ①〜④ とサンプル②を撮る）**: 訪問先でスマホを使う場面がそのまま伝わる。文字が小さく映るので、編集で拡大する。縦動画なので、横長の動画（YouTube・Loom）に載せると左右に余白が出る。余白の扱い（背景を敷く、画面を中央に置くなど）を編集で決め、PC のクリップと並べたときに画角が変わることも前提にする
- **B. PC のブラウザ**: エディタ・ターミナルの 2:30–2:50 は必ずこちら。必要なら全編もこちらで撮れる（ブラウザ幅を狭めて iPhone 幅にする。操作が安定し、文字も大きくできる反面、「訪問先でスマホ」は伝わりにくい）
- **推奨は「アプリ画面（0:20–2:30）は iPhone、2:30–2:50 は PC」の 2 クリップ**。0:00–0:20 の終わりと 2:50–3:00 の①画面も iPhone のクリップから切り出す（PC のクリップは 2:30–2:50 の 1 本だけ）

## 4. 操作手順（撮影時にそのまま追う）

移動は上のタブと下の「次へ →」だけ。画面を指でスクロールするのは、①の長い一覧、②のマスク結果、③の連絡事項カード、④のプレビューを見せるときだけ。

1. 撮影開始の状態（§3 の手順 4）: ①に「選択中: 山本 花子 さん」と患者カード。録画を始める
2. ①「患者を選び直す」→ 入口「誰の訪問ですか？」で「個人宅」（人数の小さな表示つき）→ 「五十音」の一覧（見出し「や」の下に「山本 花子」）→ **「山本 花子」の行をタップ**。同じ患者を選び直すので、会話は消えず、一覧が閉じて患者カードに戻る（別の患者の行を押すと会話が空になり「貼り付けた会話が消えます」の確認が出るので、押さない）。患者カードで赤い「申し送り・注意事項　あり」を**一度開いて**「閉じる」（ここで「介護職の方も同じ画面を使えます」と言う）→ 下の「次へ →」
3. ②「個人名を見えないようマスク処理する」→ 下線つきで強調された【患者A】（黄色ではなく、薄い青の背景）と「置き換えた記号（2件）」をスクロールして見せる。（任意）時間が余れば、②の「クリップボードから貼り付け」を一瞬見せてもよい。押す前にクリップボードが架空の会話か空であることを確かめる（iPhone の Safari はタップのたびに「ペースト」の許可を求める）
4. 「この内容で下書きを作る」→ 進行表示（秒数）→ 自動で③に移る
5. ③で「服薬」グループ（服薬状況＝悪、残薬の「要確認（残数）」）→「根拠を見る」を開く → 「指導内容（SOAP）」の S

## 5. 提出フォーム用の文案

**プロジェクト名**: 在宅レポAI（仮）— 在宅訪問の会話から報告書を下書きする薬剤師のツール
**テーマ**: テーマ1「あなたにしかない深さを」

**動画タイトル案**: 在宅レポAI — 訪問中の会話から「居宅療養管理指導報告書」を数分で下書き（Built with Claude: Japan 2026）

**プロジェクト概要（案・約 320 字）**
> 熊本で調剤薬局を営む薬剤師です。在宅訪問では、訪問のたびに医師とケアマネジャーへ「居宅療養管理指導報告書」を出します。1 枚に約 15 分、訪問が増えるほど事務が夜に積み上がります。このアプリは、訪問中の会話（文字起こし）から報告書の各欄を下書きします。氏名などの個人情報は端末内で記号に置き換えてから Claude に送り、確定後に端末内で戻します。会話に根拠のない欄は推測せず「要確認」のまま空け、本人の言葉は S にそのまま引用し、各欄には根拠の会話を添えます。AI は下書きまで、判断は薬剤師が行います。患者リスト（個人宅・施設、五十音・グループ・曜日、申し送りの表示）、新患の自動入力、宛先（医師／ケアマネ）の切替を備え、訪問先のスマホで使えます。

**Claude の使い方（回答案）**
> - **Claude API（Structured Outputs）**: 報告書の全欄を 1 回の呼び出しで JSON として受け取ります。選択式の欄は enum に「要確認」を含め、会話に根拠がない欄を推測で埋めることをスキーマで禁じています。prompt caching で報告書ルールを毎回送るコストを下げました。
> - **Claude Code の Skills**: 報告書の書式・選択肢・SOAP・「要確認」のルールを `prompts/report-rules.md` に 1 本化し、Skill（`houmon-report-rules`）とアプリのシステムプロンプトが同じ正本を読みます。`/eval-report` で評価結果を読み解き、ルールの直し方を提案させます。
> - **サブエージェント**: `pii-auditor` が、フィクスチャ・文書・サンプルに架空データ以外（実在しそうな個人情報・API キー）が混ざっていないかを独立した文脈で監査します。`report-qa` は評価の落ちた欄の根拠発話とルールの修正案を出します。
> - **フック**: `git commit` / `git push` の前に API キー形式・`.env`・「架空」宣言のないフィクスチャを機械的に止め、`.env` の読み書きも Claude に禁じています（Claude Code のフックと git の pre-commit / pre-push の二重）。
> - **使わなかったもの**: MCP。連携先（カレンダー・DB 等）が無く、評価・監査はスクリプトとサブエージェントで足りたため、目的に合わないものは使いませんでした。
> - **開発の進め方**: 設計・実装・レビューを Claude Code の並行エージェントで回し、個人情報の境界（端末外に出る経路）は毎回独立のレビューで確かめました。iPhone の Safari では端末内処理を保証した音声認識が使えないことを実機診断（`/diag`）で確かめ、アプリ内の音声認識は採用しない判断とその経緯を記録しました。締切前日の画面 v2（タブ式・患者選びを先頭に）は、データ層・タブ画面・患者選び UI の 3 担当を並列に走らせ、統合後に Playwright 29 項目の受け入れ確認と差分レビューで仕上げました。架空台本 3 本の評価で、選択式の欄はすべて 13/13 でした（`eval-results/history.md`）。

## 6. 撮影のコツ

- 冒頭の 20 秒は顔出しか写真 + 一文で「誰の・何を・どう」を言い切る。画面より先に課題を伝える
- マウスカーソルはゆっくり。タップ対象を一拍止めてから押す。「次へ →」を押す前に、押す場所（画面の一番下）を指で示すと、説明なしで使える画面だと伝わる
- 下書き生成の待ち（実測 10〜17 秒）は編集でカットし、ナレーションの「十数秒で」と画面の進行表示の秒数を合わせる
- 文字が小さく映らないよう、ブラウザの拡大率 125〜150% か、スマホ幅の表示で撮る
- 失敗テイクに備えて、山本さんと佐々木さんの下書きは事前に 1 回ずつ作り、③（連絡事項カードまで）と④（印刷・FAX とチャット）の画面をスクリーンショットしておく
