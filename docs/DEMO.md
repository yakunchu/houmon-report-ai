# デモ動画の構成案（3 分以内）

作成: 2026-11-04。提出要件: デモ動画は最大 3 分、YouTube か Loom（審査員が見られる設定）。審査のデモ項目（25%）は「冒頭で、誰の・どんな課題を・どう解決するかが明確か」。
画面録画で作る（外部配信は不要）。登場するデータは**すべて架空**（架空サンプル①②）。

---

## 1. 狙い（審査基準との対応）

| 基準 | 動画で見せること |
|---|---|
| インパクト 30% | 冒頭 20 秒: 在宅訪問薬剤師（＝自分）の、訪問ごとの報告書 15 分 → 数分。訪問先でスマホから使う。ハッカソン後も使う前提（患者リスト、2 つの宛先） |
| デモ 25% | 一連の流れを 1 分で: 患者を選ぶ → 会話を貼る → 端末内でマスク → 下書き → 確認 → 出力。失敗しない台本（架空サンプル） |
| Claude の活用 25% | Structured Outputs（「要確認」を enum で強制）、Skills（ルールの正本を人・AI・アプリで共有）、サブエージェント（個人情報監査）、フック（キー・実データのコミット阻止）、評価 13/13 |
| 深さと実行 20% | 推測しない（センノシドの残数は要確認）、本人の言葉そのまま、この薬局の書き方（O の定型、宛先別の P）、聞き返しがあれば「内容理解要確認」、新患の自動入力。リポジトリの `.claude/`・`eval-results/` を一瞬映す |

## 2. タイムライン（合計 2 分 50 秒目安）

| 時間 | 画面 | ナレーション（台本） |
|---|---|---|
| 0:00–0:20 | タイトル画面 → 自分の顔か薬局の写真（任意）→ アプリの①画面 | 「熊本で薬局をやっている薬剤師です。在宅訪問のたびに、医師とケアマネジャーに出す『居宅療養管理指導報告書』を書いています。1 枚 15 分、訪問が増えるほど夜に積み上がる。これを、訪問中の会話から数分で下書きするアプリを作りました。AI は下書きまで。判断は薬剤師がします。」 |
| 0:20–0:40 | ①患者: 患者リストで「山本 花子（架空）」をタップ → 基本情報が入る | 「患者リストから選ぶと、宛名や処方などの基本情報が入ります。氏名や住所はこの端末の中にだけ保存していて、AI には送りません。」 |
| 0:40–1:00 | ②会話: 架空サンプル①の会話が入った状態 →「マスクして確認」→ 【患者A】のハイライト、記号の対応表 | 「訪問中の会話を貼り付けます（スマホの音声入力でも入ります）。送る前に端末の中で氏名を記号に置き換え、置き換えた箇所を確認します。元の名前との対応表は画面の中だけにあって、AI には渡しません。」 |
| 1:00–1:20 | 「この内容で下書きを作る」→ 進行表示（約 10 秒。待ち時間は編集でカット可）→ ③下書き | 「下書きを作ります。報告書ソフトと同じ並びのフォームに、選択式の欄と SOAP が入ります。」 |

| 2:10–2:30 | 架空サンプル②（佐々木さん）: 「＋ 新しい患者」相当の状態 → 下書き → 「会話から読み取った基本情報」パネルに AI の提案バッジ → 「患者リストに保存」 | 「新しい患者は、氏名だけ入れて会話を取り込むと、訪問頻度や調剤形態、家族の関与など、会話から分かる基本情報が提案として自動で入ります。確認して保存すれば、次回からはリストから選ぶだけです。」 |
| 2:30–2:50 | エディタ: `prompts/report-rules.md`（ルールの正本）→ `.claude/skills` `.claude/agents` `.claude/hooks` のフォルダ → ターミナルでキー入りのコミットがブロックされる 1 カット → `eval-results/history.md` の 13/13 | 「Claude の使い分けです。報告書の書き方は 1 つのファイルを正本にして、Claude Code の Skill とアプリのプロンプトが同じものを読みます。個人情報の混入はサブエージェントが監査し、API キーや実データのコミットはフックで機械的に止めます。架空の台本 3 本で、選択式の欄は全部一致しています。」 |
| 2:50–3:00 | ①画面に戻る or タイトル | 「15 分が数分に。訪問先で、その場で下書きまで。明日からの自分の仕事を変えるために作りました。」 |

ナレーションは約 850 字。1 分 300 字のペースで 2 分 50 秒。早口にならないよう、待ち時間（下書き生成の 10 秒）は編集で詰める。

## 3. 撮影の準備（チェックリスト）

- [ ] Terminal で `npm run dev` が動いている（`http://localhost:3000` と LAN IP）
- [ ] 画面録画: PC なら Windows の **Xbox Game Bar（Win + G）** か PowerPoint の「画面録画」、OBS。ブラウザの幅をスマホ並み（約 400px）に狭めるか、DevTools のデバイスツールバーで iPhone 幅にすると「訪問先でスマホ」が伝わる。iPhone 実機で撮るなら「画面収録」（コントロールセンター）→ 動画を PC に送る
- [ ] 音声: ナレーションは後録りでもよい（画面録画と別に録って編集で重ねる）。環境音に注意
- [ ] ブラウザの状態をデモ用に整える: ① の「患者リストも含めて、この端末の保存をすべて消す」→ 「架空サンプル① 山本花子さん を読み込む」でリストに山本さんが入る
- [ ] API の残高（Console）と `.env` のキーを確認。直前に 1 回、下書きが作れることを試す
- [ ] 画面に実在の情報が映らないこと: 架空サンプルだけ使う。ブラウザの他のタブ・通知・ブックマークバーは隠す。薬局名・薬剤師名（自分）は出てよい
- [ ] 動画は YouTube「限定公開」か Loom。公開前に自分でもう一度見る

## 4. 操作手順（撮影時にそのまま追う）

1. ①で「架空サンプル① 山本花子さん を読み込む」（患者リストに入り、選択される。会話も入る）。録画はこのあと開始してもよい
2. ①の患者リストで山本さんの行を一度タップして「選ぶ」動きを見せる（すでに選択中なら、別の行→山本さん、でもよい）
3. ②「マスクして確認」→ 黄色の【患者A】と「置き換えた記号（2 件）」をスクロールして見せる
4. 「この内容で下書きを作る」→ 進行表示（秒数）→ ③にスクロール
5. ③で「服薬」グループ（服薬状況＝悪、残薬の「要確認（残数）」）→「根拠を見る」を開く → 「指導内容（SOAP）」の S
6. 「確認して出力へ進む」→ 要確認 1 件の確認 →「このまま確定」→ ④の完成テキスト → 「コピー」→ 宛先を「医療機関」に切り替えて P の末尾（「先生には〜」）を見せる（宛先を変えると下書きが古い扱いになるので、**宛先切替の見せ方は、先に医療機関で作った別テイクを用意する**か、ナレーションだけにする）
7. ①に戻り「架空サンプル② 佐々木清さん を読み込む」→ 患者バーが「未登録」になっていること → ②「マスクして確認」→「下書きを作る」→ ③の上の「会話から読み取った基本情報」（AI の提案バッジ、訪問頻度＝2週間毎、調剤形態＝ヒート or 要確認、服薬管理者＝家族、管理方法＝配薬BOX、家族）→「患者リストに保存」→ リストに 2 人
8. エディタ（VS Code 等）で `prompts/report-rules.md` → `.claude/` → ターミナルで `git commit` がブロックされる様子（例: `fixtures/` に「架空」宣言の無いファイルを置いてコミットを試す）→ `eval-results/history.md`

## 5. 提出フォーム用の文案

**プロジェクト名**: 在宅レポAI（仮）— 在宅訪問の会話から報告書を下書きする薬剤師のツール
**テーマ**: テーマ1「あなたにしかない深さを」

**動画タイトル案**: 在宅レポAI — 訪問中の会話から「居宅療養管理指導報告書」を数分で下書き（Built with Claude: Japan 2026）

**プロジェクト概要（案・約 320 字）**
> 熊本で調剤薬局を営む薬剤師です。在宅訪問では、訪問のたびに医師とケアマネジャーへ「居宅療養管理指導報告書」を出します。1 枚に約 15 分、訪問が増えるほど事務が夜に積み上がります。このアプリは、訪問中の会話（文字起こし）から報告書の各欄を下書きします。氏名などの個人情報は端末内で記号に置き換えてから Claude に送り、確定後に端末内で戻します。会話に根拠のない欄は推測せず「要確認」のまま空け、本人の言葉は S にそのまま引用し、各欄には根拠の会話を添えます。AI は下書きまで、判断は薬剤師が行います。患者リスト、新患の自動入力、宛先（医師／ケアマネ）の切替を備え、訪問先のスマホで使えます。

**Claude の使い方（回答案）**
> - **Claude API（Structured Outputs）**: 報告書の全欄を 1 回の呼び出しで JSON として受け取ります。選択式の欄は enum に「要確認」を含め、会話に根拠がない欄を推測で埋めることをスキーマで禁じています。prompt caching で報告書ルールを毎回送るコストを下げました。
> - **Claude Code の Skills**: 報告書の書式・選択肢・SOAP・「要確認」のルールを `prompts/report-rules.md` に 1 本化し、Skill（`houmon-report-rules`）とアプリのシステムプロンプトが同じ正本を読みます。`/eval-report` で評価結果を読み解き、ルールの直し方を提案させます。
> - **サブエージェント**: `pii-auditor` が、フィクスチャ・文書・サンプルに架空データ以外（実在しそうな個人情報・API キー）が混ざっていないかを独立した文脈で監査します。`report-qa` は評価の落ちた欄の根拠発話とルールの修正案を出します。
> - **フック**: `git commit` / `git push` の前に API キー形式・`.env`・「架空」宣言のないフィクスチャを機械的に止め、`.env` の読み書きも Claude に禁じています（Claude Code のフックと git の pre-commit / pre-push の二重）。
> - **使わなかったもの**: MCP。連携先（カレンダー・DB 等）が無く、評価・監査はスクリプトとサブエージェントで足りたため、目的に合わないものは使いませんでした。
> - **開発の進め方**: 設計・実装・レビューを Claude Code の並行エージェントで回し、個人情報の境界（端末外に出る経路）は毎回独立のレビューで確かめました。架空台本 3 本の評価で選択式の欄は 13/13 を維持しています。

## 6. 撮影のコツ

- 冒頭の 20 秒は顔出しか写真 + 一文で「誰の・何を・どう」を言い切る。画面より先に課題を伝える
- マウスカーソルはゆっくり。タップ対象を一拍止めてから押す
- 下書き生成の待ち（約 10 秒）は編集でカットし、「約 10 秒で」と一言入れる
- 文字が小さく映らないよう、ブラウザの拡大率 125〜150% か、スマホ幅の表示で撮る
- 失敗テイクに備えて、山本さんの下書きは事前に 1 回作って出力まで進めた画面をスクリーンショットしておく
