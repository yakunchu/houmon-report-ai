# 文字起こしの精度と端末内処理を確かめる手順（iPhone）

作成: 2026-11-06。目的は 2 つ。(1) ボイスメモの文字起こしと、ショートカットの「オーディオを文字起こし」で、同じ台本を読んだときの一致率を比べる。(2) ショートカットの文字起こしが端末内で動くか（機内モードで動くか）を確かめる。使うのは架空台本だけ。

画面: アプリの `/transcript-check`（例: `https://<薬局の PC の IP>:3000/transcript-check`）。台本の表示と、貼り付けた文字起こしの一致率の計算を端末内で行う。入力はどこにも送らない。

## 根拠（Apple の一次情報。2026-11-06 確認）

- Web ページのリンクからショートカットを起動できる（`shortcuts://run-shortcut?name=…`。「Web ブラウザを含め URL が使える場所ならどこでも」）: https://support.apple.com/guide/shortcuts/run-a-shortcut-from-a-url-apd624386f42/ios
- 実行後に別の URL へ戻り、文字出力を `result` で受け取れる（x-callback-url）: https://support.apple.com/guide/shortcuts/use-x-callback-url-apdcd7f20a6f/ios
- ショートカットの「オーディオを文字起こし」は iOS 17 で追加（音声ファイルからテキストを作る）、iOS 26 で性能改善: https://support.apple.com/en-am/111098 、https://support.apple.com/en-eg/125148
- ボイスメモの文字起こしは日本語対応（iPhone 12 以降）。「文字起こしをコピー」で全文を 1 操作でコピーできる: https://support.apple.com/ja-jp/guide/iphone/iph00953a982/ios
- ボイスメモ・メモ等の文字起こしを支える SpeechAnalyzer（iOS 26 以降）は「文字起こしは完全に端末上。モデルのダウンロードは必要」: https://developer.apple.com/videos/play/wwdc2025/277/ （セッションのトランスクリプト）
- **未確認**: ショートカットの「オーディオを文字起こし」が端末内で処理されるか、日本語の対応、「オーディオを録音」アクションの仕様。Apple の文書に記述がないため、下の手順で実機で確かめる。

## 1. ショートカットを作る（iPhone の「ショートカット」App。5 分）

名前: `在宅レポ録音`（アプリから起動するときはこの名前を使う）

| 順 | アクション（検索語） | 設定 |
|---|---|---|
| 1 | オーディオを録音 | 「すぐに録音を開始」をオン。停止は「タップ時」 |
| 2 | オーディオを文字起こし | 入力は 1 の「録音したオーディオ」。言語があれば「日本語」 |
| 3 | クリップボードにコピー | 入力は 2 の「文字起こしされたテキスト」 |
| 4 | URL を開く | `https://<薬局の PC の IP>:3000/#t=` のすぐ後ろに、2 の「文字起こしされたテキスト」を「URL エンコード」したものをつないだ URL を開く（「テキスト」アクションで 1 つの文にしてから渡す）。アプリが開き、会話欄に自動で入る。`#` より後ろはサーバーに送られない |

アクション名は iOS の版で表記が少し違うことがある。見つからないときはアクション検索に「録音」「文字起こし」と入れる。

ホーム画面にも置ける: ショートカットの「…」→「ホーム画面に追加」。

## 2. 機内モードで動くかを確かめる（2 分）

1. コントロールセンターで機内モードをオン（Wi-Fi もオフ）。
2. ショートカット `在宅レポ録音` を実行し、台本の 1〜2 行を読んで停止する。
3. 文字起こしがクリップボードに入れば（メモ App に貼って確認）、端末内で動いている強い状況証拠。**エラーになる・空になるなら、ネットワークが要る仕組みなので採用しない。**
4. 機内モードを戻す。

ボイスメモについても同じ確認をしておくとよい（録音 → 文字起こしが出るか）。

## 3. 一致率を比べる（10 分）

1. 同じ場所・同じ声の大きさで、`/transcript-check` の台本を読み上げる。薬剤師と患者の両方を読んでよい。
2. ボイスメモで録音 → 停止 → 「…」→「文字起こしをコピー」→ `/transcript-check` の A に貼る（「クリップボードから貼り付け」）。
3. もう一度同じ台本を、ショートカット `在宅レポ録音` で録音 → 停止 → 自動でクリップボードに入る → B に貼る。
4. 一致率と、「違いを見る」の中身を比べる。読み方や周囲の音でも変わるので、2〜3 回繰り返して傾向を見る。

見方: 一致率は、台本と文字起こしを 1 文字ずつ突き合わせた文字誤り率（違う文字・余分・抜けの最小回数 ÷ 台本の文字数）から出す。句読点・空白・全角半角は数えない。数字の書き方（4 と 四）の違いは数える。

## 4. 結果の記録

結果は `docs/PLAN.md` の §12 に 1 行で書く（日付、機内モードの可否、A と B の一致率、採用の判断）。

- 2026-11-06（社長の iPhone、iOS 27.0.1）: 機内モードでショートカットの文字起こしが動作。A（ボイスメモ）と B（ショートカット）の一致率は、読み間違いの範囲で差なし（数値は未記録）。→ A 案を採用し、アプリに受け口を実装（§5）。
- 同日の発見: ショートカットの検索で「ボイスメモで録音を開始」のアクションが出た。ボイスメモ側のショートカット用アクションは Apple の文書では確認できていなかったが、実機には存在する。「ボイス録音を検索」の出力に文字起こしが含まれるかは未確認。

## 5. A 案のアプリ側（2026-11-06 実装）

- ②会話の「録音して文字起こし（ショートカット）」ボタン（iPhone・iPad・Mac のときだけ表示。`src/components/ShortcutRecordButton.tsx`）。リンク先は `shortcuts://run-shortcut?name=在宅レポ録音`（`src/lib/ui/shortcut.ts`）。
- ショートカットの最後の「URL を開く」で `https://<PC の IP>:3000/#t=<URL エンコードした文字起こし>` を開くと、アプリは `#` の後ろを読んで会話欄に足し、すぐ URL から消す（`ReportApp.tsx` の起動時の処理）。`#` の後ろはブラウザがサーバーに送らないので、生の会話が PC のサーバーに届かない。再読み込みしても二重には入らない。
- ショートカットが無い端末では、ボタンを押しても何も起きないだけで、他は変わらない。Windows・Android ではボタン自体を出さない。
- 画面ロックや長時間（20〜30 分）で録音が止まらないかは未確認。止まるなら、録音はボイスメモのまま（「ボイスメモで録音を開始」のアクションがある）、取り込みだけショートカットにする（B 案）。
